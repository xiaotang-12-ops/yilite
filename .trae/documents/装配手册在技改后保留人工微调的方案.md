## 我的理解
你关心的不是“怎么把旧文案搬过去”这么简单，而是：
- 小改（2 个零件变长/变短）：3D 必变，高亮必须继续正确；说明文案可能也要变，但不想全套重跑 6 个 AI。
- 大改（换一半以上）：基本要全量重算，但也别让用户之前的人工微调全部作废。
- 规模（几万套图纸）：必须把“LLM 调用次数”压到按变更范围增长，而不是每次都全量。

## 先回答你质疑的点：A 档为什么可以“不调用其他智能体”？
你说得对：高亮跟 BOM 相关。
但在当前项目里，“BOM→3D 高亮映射”主要发生在 **Step4 的 HierarchicalBOMMatcher（确定性处理）**，并不是 Agent3/4/5/6 那些 LLM 智能体。
- Step4 做的事：STEP→GLB、解析装配层级、BOM↔3D node_name 匹配 [hierarchical_bom_matcher_v2.py](file:///d:/yilite/core/hierarchical_bom_matcher_v2.py)
- 真正昂贵的是 Step5/6/7（组件/总装/焊接安全）会循环调用 LLM [gemini_pipeline.py:L179-L205](file:///d:/yilite/core/gemini_pipeline.py#L179-L205)

所以 A 档的前提是：
- **BOM 不变**（零件代号/数量不变，只是几何尺寸变了）
- 我们复用上一次生成的 BOM 数据（output/{task_id}/step2_bom_data.json），只重跑 Step4 来更新 GLB 与 node_name 映射，然后把新的 node_name 写回手册 JSON。

这就解释了：
- 3D 变长 → GLB 变了 → Step4 重新解析得到新的 node_name → 高亮依然正确
- 不需要 LLM 再写一遍装配步骤（Agent3/4/5/6），所以成本近似为 0 LLM

## 我给你的“真正方便”的用户方案（按变更规模分流）
我建议做一个“技改更新向导”，让用户只回答 2 个问题，然后系统走最省钱且最安全的路径：
1）BOM 变不变？（代号/数量变不变）
2）装配文案要不要 AI 重新生成？（要/不要）

### 路径 A：只换 3D（或只换图），不重写文案（0 次 LLM）
适用：2 个零件变长/变短，但装配步骤文字仍然可用；用户主要要新 3D/新图 + 高亮正确。
- 系统做：
  - 替换 step_files 中对应 STEP
  - 只重跑 Step4（STEP→GLB + BOM↔3D 匹配）
  - 用新的 bom_to_mesh_mapping 更新手册里每个 step.components[].node_name / 3d_resources（这是纯数据更新，不需要 LLM）
- 用户得到：
  - 立刻看到新的 3D 形状 + 高亮仍准确
  - 之前人工微调的说明文字完全保留
  - 成本：不调用 Agent3/4/5/6

### 路径 B：只重写“受影响章节”，其余全保留（LLM 调用≈变更组件数）
适用：变长/变短导致说明确实要跟着改，但只影响少数组件/步骤。
- 系统做：
  - 先识别受影响范围：
    - 默认用“被替换的 STEP/PDF 对应的组件图 index → component_code”识别
    - 不确定时允许用户在 UI 勾选受影响组件（兜底，防误判）
  - 重跑：Step4（必要） + Step5（只对受影响 component_code 调用组件 Agent） + Step7（只增强受影响步骤）
  - 合并：只替换受影响章节；未受影响章节的用户编辑 100% 不动
- 用户得到：
  - 只换 2 个零件 → 通常只需要 AI 重写 1-2 章，而不是全套
  - 成本从“全量组件数”降到“受影响组件数”

### 路径 C：大技改（>50% 变更）全量重算，但把旧编辑尽量迁移
适用：零件换掉一半以上，整体装配逻辑都变了。
- 系统做：
  - 全量跑 Step1-8
  - 做三方合并：old_base（上次生成基线）/ user_edited（用户微调版）/ new_base（新生成）
  - 依赖稳定锚点 _legacy_step_id 做对齐（仓库样例里已存在）[assembly_manual.json:L18-L53](file:///d:/yilite/output_archive/03.02.10.0007T-AS3000-BIG%20BM清除器Big%20BM连接器/20260113_202239/assembly_manual.json#L18-L53)
- 用户得到：
  - 即使全量重算，也不是“从零编辑”，而是“冲突点复核”

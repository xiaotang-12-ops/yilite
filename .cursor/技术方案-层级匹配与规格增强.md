## 要解决什么问题（对应代码路径）
- 产品模式仅靠层级叶子名称（如“GB／T41-20001型六角螺母C级M12”）无法区分不同规格/数量的标准件，导致同名不同规格（M12/M14/M20 等）被塞到同一 BOM 行，出现过配/错配。  
  - 现有逻辑：`core/hierarchical_bom_matcher_v2.py::_build_assembly_mesh_mapping` 仅用叶子名规范化后匹配 `cleaned_parts` 的 `node_name`。  
- 层级匹配缺少 BOM code/规格信息参与，层级 key 命中后，叶子分配仍只按名称聚合。  
  - 现有逻辑：同函数中用 `assembly_name -> leaves`，未按 BOM code/规格分桶。  
- GLB 清单 `output/<task>/step3_glb_inventory.json` 中的几何名有更细的规格信息，但层级匹配未利用，导致可区分的节点未被正确分桶。  
  - 现有逻辑：`_build_assembly_mesh_mapping` 只用 `cleaned_parts`（来自 STEP 转换），未读取 inventory。  
- 产品 code 差异大的项（如 EHYG-Φ40/425 vs EHYG-φ40-φ25-250-100-V）在层级匹配失败后缺少 BOM code 兜底，导致整行缺失。  
  - 现有逻辑：`_build_assembly_mesh_mapping` 只用 product_code 与层级 key 的包含匹配，无 BOM code 回退。
- 产品模式仅靠层级叶子名称（如“GB／T41-20001型六角螺母C级M12”）无法区分不同规格/数量的标准件，导致同名不同规格（M12/M14/M20 等）被塞到同一 BOM 行，出现过配/错配。
- 层级匹配缺少 BOM code/规格信息参与，层级 key 命中后，叶子分配仍只按名称聚合。
- GLB 清单 (step3_glb_inventory.json) 中的几何名有更细的规格信息，但层级匹配未利用，导致可区分的节点未被正确分桶。
- 具体痛点：例如 BOM 行 48/52（M20*60 vs M14*60，code 不同）名称高度相似，现有流程会混淆；油缸等产品 code 与层级名差异大的项也会落空。

## 目标
- 在产品模式下，层级匹配优先，但叶子分配需要“名称 + 规格 + BOM code”联合约束，保证同名不同规格的标准件不会被归并。
- 充分利用 step3_glb_inventory.json 的几何名/规格信息，弥合 PDF/BOM 与 STEP/GLB 的命名差异。
- 对于产品 code 与层级 key 差异大的项，提供基于 BOM code 的兜底映射，避免直接缺失。

## 方案概述（计划修改的代码位置）
1) 层级匹配仍优先，但叶子分配改为“三步过滤”：
   - 名称粗匹配：沿用现有层级叶子名 → node 索引。
   - 规格精细匹配：为每个 BOM 行解析规格 token（直径、长度、螺纹等，如 M20*60、Φ40/425），对 step3_glb_inventory.json 的 geometry_name 做同样的规格 token 抽取，只有规格兼容才纳入候选。
   - 数量分配：根据 BOM 数量截取匹配到的节点，避免全部归并到单行。
2) 引入 BOM code 参与层级分桶：
   - 在 `_build_assembly_mesh_mapping` 中，当叶子名重复时，按 BOM code + 规格进行再分桶，而不是简单 set 聚合。
   - 对装配体命名差异（如 EHYG-Φ40/425 vs EHYG-φ40-φ25-250-100-V），在层级匹配失败时使用 BOM code 回退（优先 product_code，失败则 code，最后规格 token）。
3) 利用 GLB 清单建立“规格索引”：
   - 预处理 step3_glb_inventory.json，构建 `{规格token集合: [node_name]}` 索引（允许一对多）。
   - 层级匹配落到叶子时，先按层级叶子名粗筛，再用规格索引过滤，最后按数量截取。

## 关键实现点（对应文件/函数）
- 规格解析器：支持螺纹/直径/长度组合（如 M20*60、M14*60、Φ40/425、φ40-φ25-250-100），输出可比较的 token 列表；同时对 BOM 名称和 GLB geometry_name 运行，做交集判定。
- 层级映射增强：
  - 在 `_build_assembly_mesh_mapping` 中，叶子匹配流程增加“规格过滤 + 数量截取”，当叶子名重复时按 BOM code/规格分桶。
  - 为产品 code 匹配增加 BOM code/规格 fallback，避免产品 code 差异导致整行缺失。
- 数据来源：
  - 层级数据：step_assembly_hierarchy.json
  - 规格索引：step3_glb_inventory.json 的 geometry_name（node_to_geometry）和 node 名称
  - BOM 数据：step2_bom_data.json 的 code/product_code/name/quantity
- 兼容性：保留现有层级优先、代码匹配、AI 兜底流程；新增逻辑仅在层级/叶子分配阶段细化过滤与分配。

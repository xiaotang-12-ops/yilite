## 背景问题

用户在ManualViewer中遇到以下问题：
1. **跨步骤状态修改导致3D模型显示混乱**：例如在第1步把本应在第2步装的零件标记为"正在装"，切换到第2步时显示错乱
2. **需要调换步骤顺序的功能**：把某个步骤整体移动到其他位置

## 功能2：修复手动状态继承逻辑

### 问题描述

**场景举例**：
- 零件B原本在**第3步**才开始装配
- 用户在**第1步**手动把零件B标记为"正在装"（黄色）

**期望效果**：

| 步骤 | 零件B状态 | 说明 |
|------|-----------|------|
| 第1步 | 正在装（黄色） | 用户手动标记 |
| 第2步 | 已装（原色/蓝色） | 继承前面的状态 |
| 第3步 | 已装（原色/蓝色） | 虽然自动逻辑是"正在装"，但已提前装过，应显示已装 |
| 第4步+ | 已装（原色/蓝色） | 继续保持已装 |

**当前问题**：第3步可能显示混乱（显示错误的高亮或状态）

### 问题根源

**文件位置**：`ManualViewer.vue` 第3575-3612行 `resolveManualStatus` 函数

当前逻辑：
```javascript
// 向前继承：未装/正在装/已装都可继承，取最近一次
if (!status && currentStepIndex.value > 0) {
  for (let i = currentStepIndex.value - 1; i >= 0; i--) {
    // ...
    if (prevStatus === 'installing' || prevStatus === 'installed') {
      status = 'installed'  // 前面的"正在装"继承为"已装"
      break
    }
  }
}
```

问题：当零件有手动状态时，会完全覆盖自动逻辑，但这是**正确的行为**。

### 解决方案

经过讨论确认：**当前逻辑基本正确**，只需要确保：

1. **标记"未装"** → 后续所有步骤都保持"未装"（灰色半透明） ✅ 已实现
2. **标记"正在装"** → 当前步骤黄色，后续步骤变成"已装"（原色） ✅ 已实现
3. **提前装配后的"空步骤"** → 原本要装这个零件的步骤，因为已经提前装了，所以没有高亮，零件显示蓝色 ✅ 这是正确的行为

**结论**：此功能无需修改代码，当前行为符合预期。

### 验证测试用例

```
测试场景：零件B原本在第12步才装配

1. 在第11步，手动把零件B标记为"正在装"
2. 切换到第12步
3. 预期：零件B显示蓝色（已装），不再高亮
4. 步骤12的其他信息（标题、描述、工具）仍然正常显示
```

## 功能3：步骤管理弹窗（拖拽排序）

**整体设计**：

```
┌─────────────────────────────────────────────┐
│  调整步骤顺序                          ✕│
├─────────────────────────────────────────────┤
│                             │
│  ≡1. 安装底座（基准件）                   │
│  ≡  2. 安装左侧支架                         │
│  ≡  3. 安装右侧支架          ←拖拽中│
│  ≡  4. 安装顶板│
│  ≡  5. 安装侧封板                           │
│  ...│
│  ≡  65. 安装护罩                            │
│                                             │
├─────────────────────────────────────────────┤
│[取消]        [确认调整]          │
└─────────────────────────────────────────────┘
```

**实现步骤**：

#### 步骤1：安装拖拽库
```bash
cd frontend
npm install vuedraggable@next
```

#### 步骤2：添加入口按钮

在"编辑"下拉菜单中添加一个选项，或者在顶部操作栏添加一个按钮：

```vue
<!-- 在编辑下拉菜单中添加-->
<el-dropdown-item @click="showStepOrderDialog = true">
  <el-icon><Sort /></el-icon>
  调整步骤顺序
</el-dropdown-item>
```

#### 步骤3：添加弹窗组件

```vue
<!-- 步骤排序弹窗 -->
<el-dialog
  v-model="showStepOrderDialog"
  title="调整步骤顺序"
  width="500px"
  :close-on-click-modal="false"
>
  <div class="step-order-list">
    <draggable
      v-model="tempStepOrder"
      item-key="step_id"
      handle=".drag-handle"
      animation="200"
    >
      <template #item="{ element, index }">
        <div class="step-order-item">
          <span class="drag-handle">≡</span>
          <span class="step-number">{{ index + 1 }}.</span>
          <span class="step-title">{{ element.title }}</span>
        </div>
      </template>
    </draggable>
  </div>
  
  <template #footer>
    <el-button @click="showStepOrderDialog = false">取消</el-button>
    <el-button type="primary" @click="confirmStepOrder">确认调整</el-button>
  </template>
</el-dialog>
```

#### 步骤4：添加逻辑代码

```typescript
import draggable from 'vuedraggable'

//弹窗状态
const showStepOrderDialog = ref(false)
const tempStepOrder = ref<any[]>([])

// 打开弹窗时，复制当前步骤顺序
watch(showStepOrderDialog, (visible) => {
  if (visible) {
    tempStepOrder.value = [...allSteps.value]
  }
})

// 确认调整
const confirmStepOrder = () => {
  // 更新步骤顺序
  allSteps.value = tempStepOrder.value
  
  // 更新每个步骤的 display_order
  allSteps.value.forEach((step, index) => {
    step.display_order = index + 1
  })
  
  // 标记为已修改，触发自动保存
  markAsModified()
  
  showStepOrderDialog.value = falseElMessage.success('步骤顺序已调整')
}
```

## 注意事项

1. **权限控制**：拖拽排序入口应该只对管理员可见（`v-if="isAdmin"`）
2. **数据同步**：调整顺序后需要保存到草稿，发布后才会真正生效
3. **65个步骤**：弹窗需要设置 `max-height` 和滚动条，避免太长
4. **当前步骤**：调整顺序后，`currentStepIndex` 可能需要重新定位到原来查看的步骤
5. **手动状态与步骤顺序**：调整步骤顺序后，之前手动标记的零件状态（`partAssemblyStates`）仍然按 `step_id` 关联，不受顺序影响

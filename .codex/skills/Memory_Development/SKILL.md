## 工作流
**新对话开始时**
步骤1：检查 Memory_Development/ 文件夹是否存在
    ├─ 不存在 → 执行"初始化流程"
    └─ 存在 → 执行"识别流程"

步骤2：初始化流程
    ├─ 判断项目类型（ 小型：API<10个or大项目（API>=10个，有前后端分离））
    ├─ 创建对应的文档结构（小型 or 大型）
    └─ 更新模板内容（根据当前项目实际情况）

步骤3：识别流程
    ├─ 检查是否存在Memory_Development/index.md，并且按需读取文件
    │   ├─ 存在 → 大型项目模式，必读 index.md
         └─ 不存在 → 小型项目模式，必读 project.md


步骤4：评估是否需要升级
    ├─ 读取Memory_Development文件夹下其他文件夹内容，文件夹大致内容如下，自行查看了解项目


步骤5：评估是否需要升级
    ├─ 如果当前是小型结构，但项目已满足大型条件
    │   └─ 提示用户："项目已扩展，建议升级为大型文档结构？"
    └─ 用户同意后，描述如何进行升级。

├── api.md：API详细文档（按需读）

**changelog.md包含如下（仅供参考，根据实际情况做出适当调整）：**
1. **版本时间**：项目演进的关键时间点，记录修改版本和时间，例如## v2.0.64 (2025-12-24)
2. **问题根因**：问题所在
3. **问题场景**：简单描述场景
4. **修复方案**：详细并且分点说明具体修改的内容
5. **影响文件**：代码会影响的文件路径

##项目结构说明
1. 使用 `tree` 命令风格的文本展示结构。
2. 重点：在每个主要文件夹后面，必须用中文一句话解释**“这里面主要是做什么的”**。
3. 忽略 `node_modules`, `__pycache__`, `.git` 等系统文件夹。


### 3) 维护规则
- **项目快照只保留最近 3 版**；更早版本迁移到 `changelog.md`（倒序）
- API/结构/功能变更必须同步更新相关文档（（例如小型项目，那就要更新project和api文档等相关文件），禁止遗漏造成信息污染
- 若文档与代码矛盾：以代码/实际数据为准并修正文档
- 删除/修改功能时同步更新所有Memory_Development下的相关文档和更新版本号文件VERSION

## 交付标准（必须输出）
- `tree` 风格项目结构 + 每个主要目录一句中文用途说明
- API/路由/组件等清单必须用表格列出
- 版本记录包含：时间、根因、场景、修复方案、影响文件
